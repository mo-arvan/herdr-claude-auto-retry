# Design decisions

Decisions with non-obvious rationale, cited as `D<n>` from AGENTS.md, tests, and CONTRIBUTING. One entry each, newest first; the long-form rationale behind an entry lives in git history (`git log -p -- AGENTS.md`, before 2026-09-01, and the commit that introduced it).

- 2026-09-02 D38: The release channel is protected as infrastructure: rulesets forbid force-push and deletion on `main` and `v*` tags (pushing `main` is the release, so a rewrite would silently change what installers get), Actions are pinned to commit SHAs with Dependabot proposing bumps (the release job holds a write token), release tags are SSH-signed when the cutting machine has a key, and vulnerabilities go through GitHub private reporting per SECURITY.md.
- 2026-09-02 D37: Wording is checked against the installed Claude Code binary, not a live limit (its UI strings are embedded and greppable), and the forms mined from build 2.1.258 set the rules: fast-mode notices and a monthly spend cap never arm a wait (nothing a resume can fix), `try again in` is a reset-side signal only (in both lists it let one sentence satisfy the two-signal rule by itself), a reset more than a day out renders as `resets Wed 9am` and is parsed to the next such weekday, and `Unable to connect to API` plus the high-load advisory are transients. A transient wait whose screen turns into a reset banner re-derives the reset deadline instead of nudging every 30s. Known open: prose about limits in the newest block, and a wrap between `resets` and its time.
- 2026-09-02 D36: Release gates run in the tooling, not by hand: `npm run coverage` floors, nothing skipped at release (so the herdr CLI contract and Claude wording tests actually ran), the suite and leak scan in the pre-push hook because pushing `main` is the release, and CI on the same coverage command (Node 22 cells; the threshold flags need Node 22.8, so 18 and 20 run the plain suite); the adversarial review is a named checklist item. A live limit is not a gate: it cannot be scheduled.
- 2026-09-02 D35: `fake-herdr` carries a small reactive Claude TUI model (input line, vim NORMAL eating the first typed character, Escape, ctrl+u, Enter, status transitions) seeded only from captured screens, because sequence bugs across sends and screen changes (Escape into a resumed turn, ctrl+u on a draft, the read-back echo) were only testable at the unit layer where the author already had to suspect them.
- 2026-09-02 D34: A contract test runs the adapter's exact herdr CLI surface against the real binary when it is on PATH, because `fake-herdr` validates nothing and the `--custom-status` removal therefore shipped broken for a release; it targets an impossible pane id, so accepted commands fail with `pane_not_found` and a removed flag with `unknown option`.
- 2026-09-02 D33: Docs carry no per-release numbers (test counts, pinned example versions): each one needed a sync step or drifted; versioned facts live only in files versioned by nature (CHANGELOG, package.json, the manifest), and the README test badge is the CI workflow's.
- 2026-09-02 D32: Reset detection reads the newest output block plus the footer below it (everything after the block except the prompt line), the region transient detection already used (D23), instead of a fixed `detectionTailLines` window: the tail let any rendered page mentioning a limit arm a wait, while the region is located structurally on every read, needs no knob, and needs no knowledge of the user's status-line layout. `detectionTailLines` is removed.
- 2026-09-02 D31: Every reset send waits for herdr to report the pane stopped (the D28 requeue now covers all reset episodes, not just working-armed ones): a wait armed on an idle pane could otherwise fire Escape into a turn the user resumed by hand hours later; the stale-spinner send D27 allowed is dropped, since a reset limit stops Claude cleanly. Same review: `stop` signals only monitors with a live lock (a reused pid after a reboot is left alone), the quoted limit line in the log is truncated, and log files are created 0600.
- 2026-08-31 D30 (PR #3): On Escape recoveries, the typed message is read back off the `❯` input line and retyped once when the line exactly equals the message minus its first character - vim NORMAL mode runs that character as a command (17 of 20 live resumes arrived mangled); any other reading is `unknown` and degrades to the blind send, so a user draft is never cleared.
- 2026-08-31 D29 (PR #2): A rendered table row (leading `|`/`│` and 3+ separators) is never a limit candidate, because a pane writing an incident report armed a 7h wait on its own markdown table; the leading-separator rule keeps pipe-heavy status lines detectable (D25).
- 2026-08-31 D28 (PR #2): A reset limit that stays the latest output block across two consecutive polls arms the wait even while herdr reports `working` (Claude drains queued messages behind a spinner; observed hiding a limit 6.5 min), and the send still waits for the pane to stop; customPatterns-only arms fall back to `fallbackWaitHours`, and only the `⏺`-block form arms.
- 2026-08-13 D27: A stuck takeover requires Claude's OWN `⏺` error line (`agentErrorBlock`), not any block containing error text, because a `⎿` tool result quoting an API error freezes for the length of one long tool call; `blocked` pauses an episode instead of ending it.
- 2026-08-13 D26: `attempts` (reset cap, not carried) and `nudges` (backoff exponent, carried) are separate budgets, because one shared counter made a successor inherit an exhausted cap and never resume.
- 2026-08-13 D25: Only the input LINE is excluded from detection, not everything below it - Claude's status lines render below the bare `❯`, and truncating there silently downgraded real resets to the 5h fallback.
- 2026-08-13 D24: Staying in a stuck episode and being allowed to nudge again are separate questions: resumption is read from the screen plus a real `working` transition, and each nudge costs a freshly observed frozen window (a fast backoff once fired 80 takeovers in 7 minutes).
- 2026-08-13 D23: The prompt box is never part of detection - it holds the USER's draft and `send-text` appends to it, so a draft mentioning an error once drove a full recovery that would have submitted the sentence.
- 2026-08-13 D22: Escape is sent only when the pane is `blocked` or the limit is a `reset`, because Escape is the one keystroke that destroys work while a mistaken nudge merely queues a sentence - which is why the transient path can stay loose while `reset` stays strict.
- 2026-08-13 D21: A transient never fires on a `blocked` pane (a dropped connection leaves Claude idle, so the match is stale text above a live permission prompt); `blocked` stays eligible for reset menus.
- 2026-08-13 D20: The stuck clock counts OBSERVED frozen time, not wall clock, because a sleep gap is not observation (a successor once inherited a 10h "frozen" claim); a blank read never clears it, and `recover()` re-arms it.
- 2026-08-13 D19: Episode state lives in the lock record (`carriedState`), because a monitor does not survive a night (DarkWake froze all 24 locks; 9 fleet replacements in one night); `status`/`waitUntil` are deliberately NOT carried so a successor re-reads the screen.
- 2026-07-29 D18: Transient detection anchors to the latest `⏺`/`⎿` output block across the WHOLE read (a 10-item task list pushed an error 18 lines up, past the 15-line tail: a 7h stall); the tail fallback was removed by D32.
- 2026-07-29 D17: herdr's `agent_status` is a hint, not a veto - its `working` keys on a title spinner Claude leaves stale after a connection drop - so a working pane frozen on the same transient error for `stuckWorkingMinutes` is taken over; a genuinely working pane keeps producing output and never qualifies.
- 2026-07-02 D16: "You've used N% ..." banners are usage warnings, not blocked states (`USAGE_WARNING`): a week of logs showed every activation was one; `customPatterns` short-circuits as the force-detect hatch.
- 2026-07-02 D15: Config reloads at the top of every tick (deliberately no `fs.watch`: fragile across editors' atomic saves), so pattern edits apply within one poll.
- 2026-07-02 D14: A monitor self-terminates when a different live process owns its lock, and `shutdown` releases only what it still owns, so a frozen-then-resumed monitor cannot linger as a double-sending duplicate.
- 2026-07-02 D13: Transient handling reads screen structure: a neutral retry message (Claude echoes it into the input line, so a detector keyword would self-trigger), the latest-output-block anchor, and unlimited nudges with exponential backoff. Supersedes D11's one-nudge cap.
- 2026-07-02 D12: Both agent hooks trigger a full rate-limited sweep of ALL Claude panes, because herdr emits no event when restoring panes after a restart; the `[[startup]]` hook (herdr 0.7.5) covers restarts first-class and the activity sweep covers monitors that die mid-session.
- 2026-07-02 D11: Limits classify as `reset` (has a reset time: wait it out) vs `transient` (retryable server error: short backoff); 4xx is never retried, and connection patterns anchor to the `API Error:` prefix so bare prose never matches.
- 2026-07-02 D10: Detection anchors to the live footer (`detectionTailLines`) and never monitors the plugin's own pane (cwd under `HERDR_PLUGIN_ROOT`), which inherently shows limit-like text. Tail window superseded by D32.
- 2026-07-02 D9: One sidebar indicator, TTL-refreshed each tick so a dead monitor's label expires; since PR #1 it is a `retry` pane token, because herdr 0.7.4 removed `--custom-status` and the failure was silent (`run()` resolves on any exit code).
- 2026-07-02 D8: Detection is gated on the pane being STOPPED; `working` is force-stripped from `eligibleStates`, because screen text alone must never trigger a resume. Narrow carve-outs: D17, D28.
- 2026-07-02 D7: Reliability set: atomic single-monitor claim (O_EXCL), never treat a failed/empty read as "cleared", no pane reads while waiting before the deadline, cooperative SIGTERM, stale-lock detection; the double `stripAnsi` is deliberate (not idempotent on doubled-ESC input).
- 2026-07-02 D6: One `bin/main.js` dispatcher for the hook, the actions, and the long-lived monitor, for less code and per-command exit semantics (the hook never fails).
- 2026-07-02 D5: Every manifest command runs through `launch.sh` via absolute `/bin/sh`, because herdr spawns plugin commands with no shell and the server PATH; internally-spawned monitors use `process.execPath`.
- 2026-07-02 D4: `calculateWaitMs` converts the wall-clock reset to a UTC instant via the zone's actual offset, fixing a ~24h over-wait east of UTC.
- 2026-07-02 D3: Recovery sends Escape, then text, then Enter as separate calls: a bare Enter would confirm "Upgrade your plan" in the menu, and an atomic submit trips paste detection. Escape later narrowed by D22.
- 2026-07-02 D2: Monitors key on herdr `terminal_id`, not public pane id, because pane ids compact when panes close.
- 2026-07-02 D1: Event-driven herdr plugin (agent hook -> detached per-pane monitor) instead of tmux + an injected shell function, because herdr already multiplexes and exposes agent detection + pane I/O.
